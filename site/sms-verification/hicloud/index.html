FAQ

Common questions answered

Is using a temporary number for HiCloud account verification legal?+

Yes, using a temporary number for your own HiCloud account verification is legal in most jurisdictions, as long as you're not violating HiCloud's terms of service. It is a digital identity tool, not a way to compromise account security or commit fraud.

Why didn't my HiCloud verification SMS arrive?+

The most common cause is a number that was already burned from prior use or a region where HiCloud isn't actively sending traffic. Cancel the activation, select a different country, and request a fresh number; the automatic refund covers the failed attempt.

What's the difference between a one-time code and a rental number from SMSPin?+

A one-time code is a single SMS received on a number that's released immediately after the code arrives. A rental number stays active for a set period (from 1 day to 1 month), so you can receive multiple SMS messages on the same number.

Can I use a HiCloud temporary number to receive password reset codes later?+

Not reliably. A one-time number is released after the first code so that HiCloud will fail on a later reset request. If you need ongoing reset capability, rent the number for as long as you expect to need it.

What should I NOT use a HiCloud temp number for?+

Never use it to create multiple accounts for abuse, avoid a HiCloud ban, or intercept codes belonging to someone else. That's fraud and violates both HiCloud's terms and local regulations.

Does SMSPin guarantee HiCloud code delivery?+

SMSPin provides a transparent refund policy: if no code arrives for your activation, the charge is automatically refunded. There's no percentage or success-rate guarantee because no provider can promise SMS delivery.

Can I use a temporary number to verify a HiCloud account I've already created?+

Yes, you can use a temporary number for a re-verification request as long as HiCloud prompts for a new SMS verification. The process is the same as the initial signup.

API Endpoints for HiCloud OTP Requests

The standard REST endpoint for number requests returns a JSON payload with the number and its activation ID. You poll the /status endpoint with that activation ID to retrieve the SMS text once it lands. The API supports both one-time codes and rented numbers, so the integration path is identical either way. API keys are stored as plain bearer tokens and should be rotated if exposed in shared repositories.

Polling for Codes vs. Webhook Delivery

Polling intervals for SMS delivery are configurable; a 5-to-10-second interval is a healthy default. Polling is simpler to implement and works reliably when you control the retry logic. Webhooks are better suited for high-volume flows where you don't want to maintain persistent connections. For most HiCloud verification use cases, polling the status endpoint is the more straightforward approach.

Developer note: Always store the activation ID from your initial request; that's your key to retrieving the code.

Troubleshooting HiCloud SMS Code Failures

HiCloud code failures almost always come down to one of three things: the number wasn't available for HiCloud traffic when you requested it, the carrier delayed delivery, or HiCloud's gateway flagged the number. SMSPin shows you the success status per country, and if a code doesn't arrive within a reasonable window, you can cancel and re-request with a fresh number. The refund rule covers you either way.

Here's how to troubleshoot the most common failure points:

  1. Check country availability first. If the dashboard shows zero stock for a region, try a different country.

  2. Wait at least 60 seconds. Carrier delays happen; 30 seconds is normal, but don't panic at 45.

  3. Cancel and re-request. The old number is now burned; don't retry it.

  4. Check your polling. If you're using the API, verify you're polling the correct activation ID. Polling two activations for different numbers returns nothing useful.

  5. Mind rate limits. Re-requesting a HiCloud code too many times in a row can trigger rate limits on HiCloud's side. Wait a few minutes between attempts.

Re-Requesting a HiCloud OTP Without Getting Locked Out

HiCloud's rate limiting is aggressive by design. If you trigger it, you'll see the SMS stop arriving even on fresh numbers. The safest approach: wait 5–10 minutes before re-attempting, and use a different country code on your next try. A heated number (recently used for a HiCloud verification) may fail on the next attempt; fresh numbers avoid this.

The "No code received" status means the carrier confirmed delivery failure, not that HiCloud rejected your number.

If your HiCloud code failed to arrive, stop wasting time on a dead number. SMSPin automatically refunds failed activations; cancel, pick a new country, and try again. Refresh your hit rate with a fresh number in seconds.
